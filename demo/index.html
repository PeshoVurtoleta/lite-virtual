why this matters

The visible range derives from floor(scrollTop / itemHeight) — an integer. Sub-row scrolling doesn't change the integer, so Object.is halts the entire reactive chain. Renders/sec hovers near zero until you cross a boundary.

how this works

Prefix-sum offsets built once in O(n). Each scroll resolves via binary search — ~log₂(N) comparisons per event, all on a single Float64Array. Within a row the search returns the same index, so Object.is still halts the chain.

2-D cutoff

Two axes, two integer firstItems, two independent Object.is cutoffs. Scrolling diagonally moves both; horizontally moves only the column axis. Crossing a row boundary re-renders one row of cells; crossing a col boundary one column.

Both panels recycle the same pool size (~21 nodes). The difference is what runs per scroll event: lite-virtual updates only the node whose index changed; naive updates every visible node every time.

the headline

For the SAME scroll, lite-virtual writes to the DOM on boundary crossings only. Naive writes on every scroll event — that's an N× multiplier on the work the browser actually does (~21 style writes vs 1).
